## Each source in full

### `snowflake.marketplace.listings`

**Snowflake** (first party) · weekly · active

Every data product listed for sale on the Snowflake Marketplace, weekly, taken from the publisher's own sitemap.
WHY THE SITEMAP IS THE WHOLE SOURCE, AND THE LISTING PAGE IS WORTHLESS. Measured 2026-09-24 with a six-case control: a live listing, a departed listing, two garbage ids, a path with no id, and an unrelated path ALL returned HTTP 200 at exactly 68,372 bytes with the SAME SHA-256. It is one static SPA shell served for every URL under the marketplace. So the detail page carries no provider, no price, no usage count and no date -- and a 200 on a listing URL proves only that the server answered. Any probe that reads meaning into that status is measuring nothing. Do not fetch 4,039 of them.
WHAT THE SITEMAP DOES CARRY IS ENOUGH. Each entry is /marketplace/listing/<ID>/<slug> and THE SLUG IS THE PRODUCT NAME -- placeiq-daily-visit-count, lseg-starmine-quantitative-models. So the sitemap alone identifies what arrived and what left, which is the entire question. Compare wss-apify's Databricks sibling, where the URL is a bare uuid and a departed listing is unidentifiable forever.
THE CHURN IS REAL AND ALREADY MEASURED. The Internet Archive holds 46 mementos of this sitemap, and the most recent one carrying listings (2026-05-01) has 3,765 against 4,039 today. Across those 146 days: 354 DEPARTED (9.4%, roughly 22% a year) and 628 ARRIVED. A data product being withdrawn from sale is a commercial event that nobody publishes a record of.
DO NOT COMPARE AGAINST THE OLD MEMENTOS. The 2022-08-20 capture contains ZERO listings -- the sitemap did not carry them then -- so a naive oldest-versus-today diff reports 0 departures out of 0 and looks like perfect stability. Pick a baseline by counting listings in it, never by date.
NO DENOMINATOR EXISTS. Snowflake publishes no install, subscriber or usage figure anywhere reachable, so this is an arrivals-and-departures series and must never be described as a popularity one.

## Reusing this data

The captures in this repository are bytes as the publisher served them. Each
source's own licence or terms of service govern reuse — they are listed per
source above and they are not all the same. This repository's code is separate
from the data it collects; check the source before redistributing.
